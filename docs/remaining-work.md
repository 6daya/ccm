## 下一轮选择规则

先做一项跨仓分析和一项小范围开发的真实免费自然语言任务，核对能否交付、关键遗漏、人工干预、耗时与可得用量，再按既有四组方案比较专家/单高级模型。内部知识回执单独核对。选择实测最主要的遗漏/返工/耗时之一，保留 baseline 快照、同一目标和验收，报告请求数、token、时间、实际费用与质量。没有真实数据时只保留候选，不承诺节省百分比或新能力已实现。

自动知识提取/晋升、跨会话档案检索和知识平台写回仍是候选；当前仅按明确需求维护业务 docs。出现重复寻找已确认经验的问题后，再评估小范围索引，不默认引入知识数据库。

免费 verifier 的独立上下文与程序检查能降低风险，不能保证设计语义正确。语义关键遗漏若持续出现，再决定补领域不变量、换验证模型或增加限定专家审查，不让每项任务默认调用昂贵模型。

## 安全升级

0.1/0.2.x 工作台先在原位置完成/取消任务，核对未知付费并保留状态/回执；新目录取得 0.3.0，重新登记仓库、模型、保护与验收，再重启一次。不要覆盖旧 .team-harness 或新 .ccm 或移动带绝对根路径的活动任务。公司全账户约 $1000/月目标由网关统一配额管理，各工作台估算账本不能相加后假设自动硬封顶。

第二宿主适配为 P2：只有真实用户场景和可调用 SDK 确定后，提取工具/确认、模型/用量、会话/恢复三个薄接口；先过现有核心与原生链路回归。不把隐藏目录命名当作跨 agent 可运行的证明。
