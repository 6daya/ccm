# CCM 0.2.1 增量交付

> 0.3.0 已改为 OpenCode V2；本文中的 0.1/0.2.x 版本与测试为历史记录。当前使用与限制见 [V2 交付](release-0.3.0.md)。
日期：2026-10-05。基于 0.2.0/c45b6a6 保留原编排；只实施已确认的精简方案。本版不增加 agent、模型槽、知识数据库或独立调度器。

## 已实现

- 成功 run 完成后，程序从既有 state/result/check receipts 导出固定私有 `report.md`、`manifest.json`；报告 SHA256、来源真实性与未知账单保持清楚。无新增模型请求。
- 业务 accepted 和归档结果分开。原会话再次调用 complete 或 CLI `report --run ID --archive` 仅重试导出；完整档案校验后复用，不覆盖损坏或外部修改的档案。沿用已有状态锁与恢复入口，先写私有临时目录，再原子改名。
- CCM/workspace 接入校验独立 Git 根和只读状态，展示已有改动，不 reset、不切分支、不执行发现的脚本。未登记/未就绪候选不会获得访问权。
- 常见敏感路径固定规则用于业务 read/evidence/search/context/write 和 tracked Git diff。搜索的用户 glob 无法覆盖必要排除；Git diff 不启用外部 diff/textconv，不按 rename 暴露被排除的旧内容。
- 新手指引明确首次准备、自然对话、恢复、成果归属、经验按需维护、升级与当前权限限制。长期经验仍走业务 docs，未做自动晋升/自动加载。
- 修复同一主会话连续目标的用量归属：主会话消息记录到活动/最近任务，不再总归入该会话的第一个任务。实际网关账单仍不能由本地用量推导。

实现是文件名策略与既有可信工具合同，不是 OS 沙箱或全量机密内容识别。档案为记录时快照，不是账单或新的知识真实性证明。

## 已验证

本轮 47/47 程序测试通过，结果与源码摘要记录在 `validation-0.2.1.json`；程序输出在 `validation-0.2.1-tests.txt`。包括进程在归档落盘阶段退出、修复死锁并仅重试导出的回归。两项完整任务使用真实 OpenCode/Slim 和官方 Node Playwright MCP，模型使用脚本夹具，合计仍为 72 次请求；两个 run 的档案生成及幂等重试通过，重试请求增量为零。它验证调用/写入/验收/恢复/归档链路，不证明 GLM/Opus 的质量、token 或真实费用。

此前 0.2.0 的 `validation-release.json`、`validation-workspace.json`、冷启动证据继续保留为历史记录，不替换成新版本结论。
