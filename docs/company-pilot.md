# 司内真实模型质量与费用试跑

日期：2026-10-04；适用 CCM 0.3.0 / OpenCode V2。状态：方案与空白记录已交付，真实实验未执行。既有 72 次脚本请求只验证工程流程，不能混入本表。

## 开始前确认

由试跑负责人在 [记录模板](templates/company-pilot.json) 填写并确认：重点质量门槛、每组支出上限、合计上限、公司网关硬配额、人工费用口径。字段为 null 时表示未确认；不得启动付费组。约 $1000/月是目标约束，不是本方案获准花费的额度，也不是单工作台能控制的账户全局限额。首次只做每组 A、B 各一项，共八次；有明确价值且获批后才增加重复样本。

确认现有 provider 的真实模型 ID/版本、免费计费范围、付费输入/输出/缓存/推理价格及其有效日期。认证使用公司现有 OpenCode/provider 管理；不在记录、提示或聊天填写密钥。保留 OpenCode V2、CCM plugin、Node Playwright MCP 版本。网关若不提供 token 或账单，标为未知，不填写 0。

## 四组与隔离

| 组 ID | 运行方式 | 目的 |
| --- | --- | --- |
| single-free | 同版官方 OpenCode + 单免费模型，无 CCM 编排 | 免费能力基线 |
| ccm-free | CCM，专家槽关闭 | 测量运行层增益与开销 |
| ccm-expert | CCM，免费优先 + 明确价格/上限的只读专家 | 测量限定关键判断的收益 |
| single-premium | 同版官方 OpenCode + 单高级模型，无 CCM 编排 | 质量与费用基线 |

每组每项使用同一初始仓库快照、目标、必要来源与最终验收标准；业务仓库是独立 Git，逐仓记录 commit、基线文件 digest、未提交改动清单。用独立副本而非 reset 用户原仓库；每次独立工作台、OpenCode 会话、harness 状态、接收端事件集合和浏览器。单模型组仍加载相同业务规则，授予等价的仓库/内部只读来源和 Node Playwright MCP 工具；不人为削弱其验收能力。CCM 的受控拒绝本身可作为测量差异。

不复制 provider 凭据。通过已有公司受管配置引用同一连接，核对业务子仓库配置没有意外覆盖模型/工具。记录 provider 模型缓存是否可清空、热/冷条件、顺序和不可控项；网关缓存无法隔离时明确标记，轮换组顺序。依赖、浏览器已准备好的运行延迟与首次安装时间分开记录。单模型组选定业务起始目录，CCM 在中央根目录启动；这项目录差异需要记入记录。

## 自然语言任务

A：用户可以正常说“分析这几个仓库的订单链路，解释调用关系、模块责任和失败传播。为我们改善订单失败定位提出建议，给出来源，缺失或冲突信息明确列出。”提供同一相关内部知识来源和三个仓库；若意图可能指向两个项目，四组使用同一个歧义，不预先透露正确项目，记录澄清及错误选择。

验收者事先建立带文件/行、内部 URI/版本的参考清单：入口、gateway/orders/payments 链路、责任归属、健康检查与业务成功差异、失败传播、未知信息以及与需求有关的建议。按清单逐项记满足/缺失/错误；不能只判断文字是否流畅。

B：用户可以正常说“给订单页面补充可观测，让我们能把点击和后端链路关联起来，避免重复上报与个人信息。先确认业务模块和公共模块的边界，完成小范围修改，并用 Playwright MCP 验证。”四组共享同一字段规范、origin、固定命令和真实浏览器验收：一次点击一次 order_submit，仅含 orderId/traceId，traceId 来自页面并可与接收端对应，公共 transport 保持中立。

不要用 EVAL 标记、预设任务图、预置专家答案，或要求模型故意写错文件来测量智能调度。机械边界故障注入另行记录。若测试恢复，在四组相同阶段（已有中间交付、仍有剩余实现）中断并在原会话说“继续”，记录原/恢复会话、完成的专家请求与是否重复。模型未主动调用专家也是合法结果，按理由与质量评审，不强制恰好一次专家。

素材可参考 eval/fixtures.mjs 与 eval/case-server.mjs 的验收定义。eval/run.mjs 和 eval/gateway.mjs 是模拟模型回归入口，不能用作真实模型质量试跑。真实试跑通过正常 OpenCode 对话进行，目标和任务图由模型根据用户意图形成。

## 记录与判定

每次复制空白 JSON，填写实际运行和原始证据位置。每个请求按角色与阶段记录：决策、工具后续、验收、恢复；同时记输入/输出/缓存读取/缓存写入/推理 token、耗时、模型版本、付费原因、账单 request ID。token 类别可能重叠，使用网关说明解释，避免重复计费。自动统计拿不到的角色/阶段写 unknown，不用猜测。

任务级记录澄清次数、错误项目/模块选择、关键遗漏、人工干预、首次验收、最终验收、返工分钟、总耗时、中断恢复、实际拒绝与回执。人工不得悄悄帮某组改目标或提供专家答案；额外资料和干预均记入日志。验收者先依据同一清单审查结果，再查看组别和费用；可行时匿名评审。

报告同时列出未通过/超时/取消的全部尝试及其成本，不能只比较成功请求。首次验收率 = 首次通过数 / 全部尝试数；每次成功交付的模型费用 = 同组所有尝试的已核实网关费用 / 最终成功数。成功数为 0 或账单缺失时指标为未知；不得把缺失账单视为免费。人工成本只有负责人确认费率后才合并，模型费用与人工时间始终分别展示。

估算偏差记录估算减实际的美元差值；实际费用为零时不计算相对百分比。质量先按负责人确认的门槛判定，再在达标组中比较成本和总时间；不预设提升百分比。先汇报小样本观察和限制，不能据八次运行宣称普遍优势。付费账单未知、网关额度接近上限或关键边界失败时停止追加试跑并核对。

内部来源接入按照 [MCP 验证步骤](internal-mcp-validation.md) 单独留存真实回执。P2 决策见 [后续计划](remaining-work.md)。
